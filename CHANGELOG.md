# Changelog

Significant changes only (CLAUDE.md rule 5): one line per change, 1–2
sentences — essence and intent, not content.

- 2026-08-22: **two landing claims about the demos are cut back to what is actually demonstrated (K-877, K-878).** The repeat grocery order was attributed to real Stripe; the only scripted second-order-on-a-saved-card beat runs against stripe-mock, so the line now says that and credits real Stripe with the part it genuinely covers — the off-session charge on a saved card, in test mode. And the philslist card told a reader to attach a photo of the bike, which philslist has no path for and would refuse as an undeclared property; it now says the board is text-only and, more usefully, that the contact detail a seller gives goes in the listing text and is public. Intent: the first sentences a Show HN reader can check against a live demo are the most expensive ones to get wrong.

- 2026-08-22: **the spec says a catalog may be derived from operator data, and that publishing a row must never need a deploy (K-922, Phil).** §8.3 stated flatly that the catalog "changes only when the operator deploys", and §9.1 told operators that a set derived from their own data is a constraint a schema cannot express and belongs in a handler guard — so the spec both forbade the shape and mis-taught the alternative. It now permits a data-derived descriptor and pins the three things that make it safe: the document MUST state the current value rather than one captured at boot, the version parameter MUST move with it, and it MUST NOT vary by caller, since a per-identity catalog is not the shared public document the whole caching design rests on. Intent: a provider's surface changes when its shelves do, and a spec that only admits deploy-time change quietly requires one.

- 2026-08-22: **the onboarding page and the descriptor house style teach one handler mixin instead of two (K-921).** Both told an operator that "a controller declares queries or actions, never both" and showed `include Kiosk::Query` / `Kiosk::Action`; the reference has since collapsed those into `Kiosk::Handler` with a per-declaration `kind` macro, so the sentence was false and the copyable snippets no longer boot. Nothing normative moved — neither the narrative nor the formal spec ever said anything about Ruby class organisation, which is the right division and was verified rather than assumed. Intent: the page an operator copies from must compile against the gem they install.

- 2026-08-22: **the spec now says the `rel="kiosk"` signal must name a versioned cut and must not name the alias (K-927).** §4.5 asked only that the `href` point at "the universal skill on kiosk.tech", and every example on this site — the normative one and both onboarding snippets an operator copies — showed `skill.md`, so the shared artefact was the one thing in discovery that carried no version and no digest and could change under a reader without notice. The narrative and formal specs gain the requirement plus the coherence rule that the signal and the `kiosk.json` `skill` pin name the same URL, and onboarding now teaches reading it from configuration. Intent: both of an origin's discovery signals should be immutable and hash-pinnable, or the weaker one defines the guarantee.

- 2026-08-22: **the spec states what `POST /auth/unlink` answers: `204 No Content` (K-870).** §6.2 documented the responses of the two sibling endpoints of the same ceremony and said nothing about the third, and the gap was filled on the wire instead — an undocumented `{ok: true}` body that ran for four months. The body is withdrawn and the status is written down beside its siblings. Intent: an endpoint whose neighbours document their responses cannot leave its own unstated without someone inventing one.

- 2026-08-21: **the prose half of the relink inventory is a build gate now, and the four sites that had already rotted are corrected (K-863, K-745).** `bin/check-skill-immutability` held the bytes but read no sentences, so the formal spec still called 0.4.2 the current skill and the illustrative `skill` pins on the narrative spec and in the schema examples still named `skill-v0.4.0.md`, three cuts behind. A fourth pass now derives every expectation from the cuts on disk — the current-cut sentences, the two version ranges around them, every example pin URL and the cut table — while a bare cut name in prose is left alone as history. Intent: a version line on a normative page tells an adopter which cut to pin, so it is a claim the build has to hold, not a number someone has to remember.

- 2026-08-21: **`quota_exceeded` describes what an operator does with it, not a gem that does not exist (K-586).** §9 reserved the code "for the quotas companion" and said the core operator never emits it; there is no quotas companion in the fleet, and the first real quota — a per-principal cap on outstanding KYC verifications — is enforced by an operator's own handler. The table row, the specification's copy of it and the published problem page now say that, and name the one thing this code means that no other refusal in the vocabulary does: come back later. Intent: a closed vocabulary's entries have to describe the wire, not a roadmap.

- 2026-08-21: **`pay` is idempotent: replaying a settled chain returns the settlement, not an error (K-850, ADR-0026).** §11.6 already made the identical-chain retry the required one; it answered it with a `409` that carried none of the facts the assistant was missing, which left a reconciliation read — and a per-user paid-state query on every operator — as the price of a lost response. The operator half now says which two cases a re-presented chain falls into and what each is answered with, `409` narrows to "seen and NOT settled", and the assistant's retry branch loses a step in both specs and in the skill. Intent: idempotent means the replay returns the original result, and a 4xx cannot be that.

- 2026-08-21: **`skill-v0.4.3.md` is cut, the alias is byte-identical to it again, and the guard now enforces that it stays so (K-847, K-848).** The published sentence that `skill.md` carries the newest cut's exact bytes had been false at head for days because the alias was where notes were staged between cuts — a practice `bin/check-skill-immutability`'s own header sanctioned. The sentence is made true instead of softened: the guard drops that permission, adds an at-rest alias-≡-newest-cut and frontmatter-version check, and the new cut also carries K-848's widened list of operator-authored surfaces an assistant reads as data (`$comment`, `default`, problem-document extension members). Intent: a claim about a supply-chain control is either enforced by the build or it is decoration.

- 2026-08-21: **`Kiosk-Min-Client` and `kiosk.min_client` are one number, and the spec now says so (K-747).** Both surfaces were described as advisory and neither was said to equal the other, which left an origin free to publish two different values — the reference did exactly that for any operator who set the knob. Intent: two publications of one fact must be pinned to each other, or a reader has to guess which one counts.

- 2026-08-21: **The cart mandate says how many line items make a cart: at least one (K-857).** Requiring the field (K-741) left `[]` conforming, which withholds the reconciliation trail the requirement exists for while the mandate still authorises a positive charge. §11.2 states the MUST, the schema states `minItems: 1`, and the reference verifier refuses the same set. Intent: a rule whose stated purpose is defeated by a value it admits is not yet the rule.

- 2026-08-21: **`header_nonce` gets the u32 bound the prose always claimed for it (K-842).** The PoW schema described the field as a u32 and then declared an unbounded integer, so the normative document admitted values the reference verifier folds down to a different number — the bound is now stated inclusively, the same spelling `indices` uses (K-845). Intent: where a schema and a verifier disagree about what a proof IS, one proof has more than one legal spelling.

- 2026-08-21: **The landing page stops selling 0.3's wire.** «four fixed verbs, one envelope» described the multiplexed `POST /query` + `POST /run` pair and the `{ok, data, error}` success envelope, both of which 0.4 removed outright — the answer to «why not assemble the standards yourself» was pinning a layer that no longer looks like that. It now says what 0.4 pins: one endpoint per verb over a published catalog, and one error envelope (RFC 9457 problem+json). (K-859)

- 2026-08-21: **The onboarding walkthrough stops describing a generator and a wire that no longer exist, and its "verify it works" step stops being scoped to itself.** It told adopters `rails g kiosk:install` emits ten migrations (six since the migrations-from-scratch rebuild), framed discovery as "three hooks" immediately after the step that installs six discovery documents, wrote the auth plane without the `/kiosk` prefix the rest of the page insists on, and showed self-registration as the only way an assistant gets a token. The verification block was the sharper defect: it walked exactly the path the page teaches, so an app serving none of the ceremony or discovery the mount promises would still have run it green — the page's own check could not have caught the page's own gap. It now probes all six discovery documents and the binding ceremony directly. (K-854, K-725, K-726, K-727)

- 2026-08-21: **Every RFC 9457 `type` URI the wire mints now resolves.** All fifteen `https://kiosk.tech/problems/<code>` URIs 404ed: the shape was pinned in the gem, in `problem.schema.json` and in the e2e harness, and nothing was served at the other end — so the first thing a developer does with a `402` (paste the URI into a browser) hit a 404 page. Each code now has a page carrying its meaning, its HTTP status, what it carries and what to do next, plus an index; `bin/check-problem-pages` holds the published set against the specification's vocabulary table so a code added to the wire cannot quietly acquire a dead URI. The URI shape is unchanged and deliberately so — it is an identifier, and the `code` member stays the contract. (K-793)

- 2026-08-21: Spec (formal §11.1 + `mandates.schema.json`) — **`line_items` is now REQUIRED on the cart mandate.** It was optional while the settlement and reconciliation path already depended on it, so an assistant could legally omit it, still pay, and leave the operator holding a capture it cannot match to any domain object — a degraded audit trail with no error raised anywhere. The cheaper alternative (leave it optional; tell each operator to reject the omission itself) was declined because it makes the same field mean different things at different origins. Both narrative surfaces already listed it as a cart field, so only the formal spec moved. (K-741, decision LINE-ITEMS-REQUIRED)

- 2026-08-21: Spec (narrative account-binding + formal §6.3) — **a re-bind to the account a key is ALREADY bound to is now stated to be idempotent, and the spec's silence about it was the defect.** Both documents justified killing a key's pre-link tokens "because a rebind is a principal change" — a cause a re-link plainly lacks — while the shipped behaviour revokes and re-issues anyway. Rather than make the security path conditional, the rule is now written down as it behaves: the ceremony still succeeds, still re-issues, the previous tokens still stop verifying, and the response is indistinguishable from any other rebind's. No wire field moved and no version bumped. (K-787)

- 2026-08-21: Spec (formal, §11.6 reference note) — **the operator-half example stops being one demo's boolean and becomes the fleet's tri-state.** The note described getgrocery's `my_orders` "paid flag"; all three paying demos now claim the row before the capture, flip it the instant the capture returns, and publish `payment_state` (`unpaid` | `pending` | `paid`) on their per-user query — so the note names the shape a reader should copy rather than the one field it happened to be built on. Non-normative; the requirement above it is unchanged. (K-853)

- 2026-08-20: Spec (narrative + formal §11.6, §16.1/§16.2 conformance) + skill — **a `pay` reconciliation that finds no record must never be read as "no money moved".** An operator captures and records the capture in two steps, so between them its own records show an already-charged cart as unpaid; §11.6 previously told an assistant that a confirmed-unpaid order is exactly when a freshly signed chain is correct, which turns that gap into a second real charge. The rule now fails safe in both directions: an operator MUST anchor the paid state it publishes for reconciliation to the capture and answer *pending*/*unknown* rather than *not paid* while a capture may be outstanding, and an assistant may re-sign ONLY on a positive, unambiguous "not paid". (K-851)
- 2026-08-20: Spec (narrative + formal, new §11.6 + the `conflict` row) + skill — **`pay` says what its idempotency key is, and tells an assistant what to do with a `pay` response that never arrived.** The string "idempot" appeared nowhere in either the formal spec or the skill, so the only thing between an at-least-once network and a double charge was the assistant guessing: the identical chain is already safe (the mandate `id`s are unique per `user_id`, so a resend is refused `409 conflict` before any capture), but a client that answers a lost response by MINTING A FRESH CHAIN collides with nothing and is charged twice — and the skill's only retry advice, written for a `payment_failed` it actually received, said to re-sign. §11.6 now states the operator's duty (reject a re-presented mandate `id` with `409` before capture; key the PSP capture by the cart `id`) and the assistant's (retry the IDENTICAL chain byte for byte, never a fresh one; on `409` reconcile through the operator's own per-user query before signing anything new), and `skill.md` carries the same rule where an assistant will meet it. No new wire field: the chain was always the key, it was simply never written down. (K-739)
- 2026-08-20: Spec (narrative + formal, §7 + §16.1) — **the identity-binding contract stops promising a `403` it never had for reads, and says out loud that the MUST is the operator's.** §7 closed with one sentence — "cross-identity reads and writes fail (`403 forbidden` or `403 rls_denied`)" — that no conformance evidence anywhere backs for a read: the reference's isolation flows prove a foreign row ABSENT from an answered `200`, and its own red-team oracle deliberately refuses to score an unanswered query as isolation, because an empty result and a failed request look identical on the wire. The requirement now names the two outcomes separately — a call that names no foreign row is answered with them filtered out and MUST NOT be refused merely because other principals' rows exist; a call that NAMES a foreign row MUST be refused `403` — which is what the demos already demonstrate on both legs. The reference note stops implying the identity GUC is the filter and records that it is not: RLS is unbundled and opt-in and the role backstop is off by default, so the invariant is carried by each registered query and action. Nothing in the reference moves; what moves is that the strongest normative sentence in the spec is now true of it. (K-737)
- 2026-08-20: Spec (narrative + formal §15.9) + skill + descriptor house style — **the injection rule stops being about the SKILL only and starts covering the text an assistant actually reads.** §15.6 forbade loading executable instructions from the operator and closed with one sentence scoped by its own parenthesis to "schema, prices, availability" — which named none of the operator-authored NATURAL LANGUAGE that ADR-0023 makes load-bearing: verb and per-property `description`s, `enum` members, `example_params`/`example_row`, `owner`, an error's `title`/`detail`/`hint`, and every string in a result row, including text an operator's own end users wrote and it merely relays. The new §15.9 enumerates that surface, requires an assistant to treat all of it as data about the service and never as an instruction to itself, spells out the six things it may not be allowed to do (override the human's limits, route around a cap or a KYC gate, skip a human-in-the-loop step, move a key, trigger a fetch, leak across origins), and states the tiebreak ADR-0023 already decided for authors from the assistant's side: where a `description` contradicts a schema, the schema is right. The operator's half is a rule about SUBJECT, not tone — describing your service is the field's purpose, addressing the assistant's own policy is not — and the house style now says so where descriptors are written. Stated as a requirement and explicitly NOT as a mechanism: nothing filters or signs operator text, and what the section fixes is where the conformance failure lies when such text is followed. (K-742)
- 2026-08-20: Spec (formal, §10 + `spec/schemas/pow.schema.json`) — **the u64 index bound is now stated INCLUSIVELY, because the exclusive spelling refused the largest legal index in every double-precision validator.** `exclusiveMaximum: 2**64` is exact in Ruby and wrong on kiosk.tech: a reader that parses JSON numbers as IEEE-754 doubles rounds `18446744073709551615` onto exactly `2**64` and then refuses it, so a third party implementing against the NORMATIVE copy would have rejected proofs the reference accepts. `maximum: 2**64 - 1` is the same set for an exact reader and survives the round-trip for a lossy one; an accepted example now pins the largest legal index, and the over-range rejected example moves to the first magnitude a double can still tell apart. Intent: the published schema is the artifact a porter runs, and a bound that is wrong only at its own edge is wrong in the direction that punishes honest work. (K-845)
- 2026-08-20: Spec (formal, §10 + `spec/schemas/pow.schema.json`) — **a PoW `nonce.indices` element is now BOUNDED to the u64 its description always claimed.** `items` was a bare `{"type": "integer"}`, so the schema admitted proofs every conforming verifier refuses: a verifier packs an index as a little-endian u64, `idx` and `idx + 2**64` are the same leaf, and the reference has rejected the out-of-range spelling since it stopped hashing before checking. The bound is `[0, 2**64)` in the schema and a **MUST** in the formal prose, with the aliasing reason beside it; two rejected examples pin it so the constraint cannot go soft unnoticed. Intent: the formal spec must not describe a wider accepted set than any implementation has — an implementer reading it would ship a client that gets 400s. (K-839)
- 2026-08-20: Spec (narrative + formal, §3.7.3) — **the shared-cache prohibition names the third directive it was always about: `must-revalidate` joins `public` and `s-maxage`.** The sentence says in its own words that it exists so an operator need not rely on the RFC 9111 §3.5 default, and that default has THREE doors, not two: a shared cache may reuse an answer to an `Authorization`-bearing request when the response carries any one of them — and every verb request carries `Authorization`, so `must-revalidate` beside a `max-age=N` with no `private` is the same cross-tenant leak `public` is. One word in each of the two normative sentences (and in §8.4's restatement), with the reason written beside it. The reference already blocked all three, so nothing in the code moves; what moves is that a conformance sweep can now read the rule off the text instead of off the implementation. (K-826)
- 2026-08-20: Spec (narrative) — a reference note records that the reference's `agent_id` is a **uuid** and its pluggable agent-IdP seam does not widen that. Non-normative and deliberately so: the wire says nothing about identifier shapes, but `user_id`'s type is configurable while `agent_id`'s is not, and an adapter fronting an external agent-identity issuer would otherwise discover that at a settlement or an RLS cast rather than at the seam. (K-830)
- 2026-08-20: Spec (formal, 12.2) — **the reference's KYC-attribute storage note names a TABLE instead of a column.** The reference now records one row per granted name in `kyc_attributes` rather than a jsonb map on the agent row, so the grant is a row's existence and there is no stored value whose spelling a reader could misread; the normative sentence around it is untouched — an operator still MUST honour only literally-`true` values and MUST NOT store the underlying documents. Storage was always an implementation detail, and this note is the only place either spec named it. (K-656 / T-061, decision KYC-ATTRIBUTES-TABLE)
- 2026-08-20: Spec (narrative) — **the audit-trail reference note is rewritten: the reference no longer KEEPS an audit trail, it OFFERS one.** Phil reversed the direction the same week, so `kiosk.action_log` is gone from the reference's schema and an operator-set sink receives one event per `run` invocation instead — with no sink configured, nothing is emitted and nothing is stored. The note now says that, and says the part an implementer should not have to find in source: the arguments arrive UNREDACTED and the operator owns the PII decision, with one-call redaction offered rather than imposed. Still non-normative — the wire is unchanged and nothing in the formal spec or the JSON Schemas moves. Supersedes the note added earlier the same day. (K-828)
- 2026-08-20: Spec (narrative) — **a reference note records that the reference implementation keeps an audit trail, and what it deliberately does not put in it.** Every `run` invocation lands one row in `kiosk.action_log`, success or failure, written after the action's own transaction and outside the identity-scoped session so a caller can neither erase nor forge one; argument VALUES are withheld by default (names and JSON types only) and verbatim capture is an explicit operator opt-in. Non-normative — the wire is unchanged and nothing in the formal spec moves — but it is behaviour every adopter of the reference inherits, and a privacy-shaped default that an implementer reading the identity-binding contract should not have to discover from the source. (T-088, K-791 decided by Phil 2026-08-17)

- 2026-08-19: Descriptor house style — **the guide stops running ahead of the protocol and starts citing it, and its worked example stops teaching the one defect the fleet just removed.** In 0.3 this page asked for schemas the wire called optional; the spec has since passed it, so the voice is inverted: a new preamble hands `input_schema`/`output_schema`/`params` back to §8.3 and keeps only what is genuinely stylistic, and the paragraph claiming the formal descriptor schema "does not yet name" `output_schema` is deleted rather than softened — it names it and requires it. Two rules the guide never had are added because they decide what a verb IS, not merely how it reads: a query's arguments travel in the query string, so its inputs are ONE LEVEL with SCALAR leaves and anything richer **MUST** be an action; and `limit`/`cursor` are reserved names a verb never declares, with the consequence spelled out — a page-size clamp cannot live in a schema, so `description` is its only legal home, a carve-out of §1's prohibitions rather than a contradiction to be discovered. The worked example is re-derived from the shipped `search_hotels`: business filters only, ONE `output_schema` (a truncated page is the same array as a complete one), and a "pagination: what goes where" block saying the body never changes, the cursor is a `Link` header, and the ABSENCE of that link is the only completeness signal. Intent: this is the page an operator reads while writing the descriptors an assistant will be driven by, and a writing guide that is weaker than the spec it companions teaches drift. (T-068 slice 7, K-798)

- 2026-08-19: Landing + onboarding — **the two pages that TEACH the wire stop describing 0.3.** `onboarding.html` taught `POST /kiosk/query` with a JSON body and `jq '.rows'` in a copy-paste block a reader would actually run, told them `GET /kiosk/schema` needs a Bearer token, printed `capabilities` as a verb list, called both schemas optional, and shipped a worked `my_orders` verb with no `output_schema` — which since 0.4 does not boot. It now teaches one endpoint per verb, the public catalog, query-string arguments, the bare-array success body, RFC 8288 pagination with link-absence as the completeness signal, and the RFC 9457 problem document a refusal actually is (with the handler-side `{ error: { code } }` spelling kept and distinguished from it, because that half is still true). - 2026-08-19: Spec (narrative + formal) + skill `skill-v0.4.2.md` — **§14.2's additivity promise is scoped to 1.0 and later, and the two public self-descriptions are put on one footing: `GET <endpoint>/openapi.json` is unauthenticated and untolled exactly as `GET <endpoint>/schema` is.** The first half resolves a contradiction the tree was carrying: the spec promised that no response field is removed inside a MINOR series, and 0.4.1 removed a paginating query's `next`. Rather than paper over it, the promise now begins at 1.0 and the text says WHY in the same breath — before 1.0 the compatibility mechanism is the operator's pin (one exact immutable cut plus its SHA-256, adopted before transacting), `Kiosk-Min-Client` is the advisory signal that a client is behind, and there are no third-party adopters for a cross-patch guarantee to protect. It is deferred, not withdrawn: at 1.0 it binds, and a wire change after that is a MINOR bump. The second half removes the last gated description of a wire whose every other description is open — the same registry in another dress — and specifies what comes with being public: `public` caching with a short freshness lifetime on the fixed path, a strong `ETag`, **no `Vary` at all** on any unauthenticated document, and §4.1's version parameter on the url a pointer document links. That lifetime is now written as what it actually is — the post-deploy staleness an operator accepts, around a minute — rather than as a cache-efficiency knob; the load is carried by the immutable versioned url. Intent: a normative promise that is false on the day it is published costs more than the compatibility it pretends to offer, and one wire must not hold two trust states for two spellings of the same catalogue. (K-806 = (b), K-804 = open it, and the pointer `max-age` 300 → 60 — all Phil, 2026-08-19)
- 2026-08-19: Spec (narrative + formal + descriptor JSON Schema) + skill `skill-v0.4.1.md` — **pagination adopts RFC 8288 (Web Linking): the `next` cursor leaves the response body and travels as `Link: <…>; rel="next"`, with `X-Total-Count` carrying the total.** The consequence is the point rather than a side effect: a paginating query answers the SAME bare array as every other query, so §8.2's shape table collapses from four shapes to two — a query answers an array, everything else answers its own object — and a paginating verb declares ONE `output_schema` instead of a two-branch union covering "truncated" and "last page". `X-Total-Count` is written into the text as what it is, a widely-used DE-FACTO CONVENTION with no RFC behind it, adopted by choice and never cited as a standard; the References section gains RFC 8288 and not it. §9 also gains **§9.1, the three-way rule for a bad argument** — a value outside its domain is `400` NAMING the valid values, an identifier that addresses nothing is `404`, a filter that matched nothing is `200 []` — with the discriminator (does the argument ADDRESS an entity or FILTER a collection?) and the recorded `400`-over-`422` trade-off written down so it is not rediscovered as a defect. Intent: pagination is transport metadata and HTTP already has a place for it; taking that place deletes a whole response shape, and a status that distinguishes "wrong value", "no such thing" and "nothing matched" is the difference between an assistant that can recover and one that guesses. (T-092 decision `PAGINATION-RFC8288`, T-090 three-way rule — both Phil, 2026-08-19)
- 2026-08-19: Spec (narrative + formal + two JSON Schemas) + skill — **`GET <endpoint>/schema` becomes PUBLIC and untollable**, `/.well-known/api-catalog` hyperlinks every verb an origin serves without a credential, and the catalog's `verbs` field is **deleted**. One idea in three places: a verb roster is not a secret, so gating it while every discovery surface stood open withheld nothing and cost an explanation — and the toll went with the gate, because a toll prices a caller and that endpoint resolves none. §4.2's **MUST NOT** on publishing verb names survives with its justification replaced: it was a security rule resting on three defences, and it is now a modelling rule about pointers versus copies, because two of those defences are gone by decision. Caching is the other half and is specified rather than left to a deployment: the catalog is `public` with a strong `ETag` and **MUST NOT** carry `Vary: Authorization`, and a new REQUIRED `kiosk.schema_url` lets an operator hang a version on the URL (`?v=<digest>`, derived from everything the document is rendered from — an implementation upgrade included) and serve *that* immutable for a year, while the short-lived discovery document republishes the link. `verbs` went because it rendered the same value `capabilities` does, so it was one fact under two names; the descriptor schema's root is now closed, and the rejected example that used to test the `verbs` enum is replaced by one that carries the field. Intent: the catalogue is what makes a Kiosk origin self-describing, and it should be as reachable and as cacheable as the document that points at it. (T-094, T-093, T-095; K-799, K-801 decided by Phil 2026-08-19; `/kiosk/openapi.json` stays gated — that is K-804, undecided)
- 2026-08-19: Skill — `skill-v0.4.0.md` is cut and `skill.md` moves with it: the wire it teaches is one endpoint per verb (`GET <endpoint>/<query-name>` with query-string arguments, `POST <endpoint>/<action-name>` with a JSON body), a success body that IS the result with no envelope around it, and errors as `application/problem+json` whose branch point is the TOP-LEVEL `code` — not `error.code`, because a problem document is flat.
